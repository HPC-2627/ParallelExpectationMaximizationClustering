All the datasets used by the project: 3 **synthetic** profiles (for scaling and correctness), 5 synthetic **sweep** files (cost of an iteration vs $D$, plot P1) and 10 **real** datasets (mostly medical, for the clustering quality). ## 2. File format

All the datasets (synthetic and converted real ones) use the same binary format:

- `<name>.bin`: an 8-byte header with two `int32` (N, D), then $N \cdot D$ `float64` in row-major order, little-endian.
- labels: one `int32` per row in a separate file, `<name>_labels.bin` for the real datasets (only when a categorical label exists) and `<name>_pPP.labels.bin` for the synthetic ones ($-1$ = outlier).
- `<name>.json`: metadata (columns, standardization parameters).

Every column is standardized (z-score).

```c
FILE *f = fopen("data/synthetic/synth_clean/synth_clean_p04.bin", "rb");
int N, D;
fread(&N, sizeof(int), 1, f);
fread(&D, sizeof(int), 1, f);
double *X = malloc((size_t)N * D * sizeof(double));
fread(X, sizeof(double), (size_t)N * D, f);     // X[i*D + d] = variable d of row i
fclose(f);
```

Why this format:

- **Binary, not CSV:** one `fread`, no text parsing, much smaller (8 bytes per value instead of 15–20 characters). The reading time is part of the measurements.
- **`double`:** EM sums many numbers and computes `exp` and `log`; double precision keeps the parallel versions identical to the sequential one.
- **Row-major:** the rows of a rank are a contiguous block, so every rank reads only its own rows (`fseek` or MPI-IO).
- **8-byte header:** describes the file and keeps the doubles aligned to 8 bytes.
- **Labels in a separate file:** EM never sees the truth, and the data file stays a clean matrix.

## 3. Synthetic datasets

Generated by `src/dataset-managed/generate-synthetic-dataset.py` into `data/synthetic/<profile>/` (deterministic, seed 42).

### 3.1 Why synthetic data

- The real datasets carry too little work per iteration ($N \cdot K \cdot D$; even `brainweb`, with 11.9 M rows, has $D = 1$): communication weighs more than computation and no scaling is visible. Weak scaling needs a size that grows with the number of processes, which only generated data allow.
- The truth is known (true subgroup and true parameters): all the versions can be checked against each other and the clustering quality can be measured.
- 3 profiles cover an easy case, a realistic one and a hard one. $K$ and $D$ change too, because an iteration costs about $N \cdot K \cdot D$.

### 3.2 The three profiles

| | `synth_clean` | `synth_overlap` | `synth_rare` |
|---|---|---|---|
| Role | easy, satisfies the model | realistic | hard |
| Clusters $K$ | 4 | 5 | 6 |
| Variables $D$ | 10 | 20 | 50 |
| Cluster weights | 25% each | 30, 25, 20, 15, 10% | 40, 25, 18, 12, 4, 1% |
| Separation $\delta$ (in standard deviations) | 6.0 (well separated) | 2.5 (overlapping) | 4.0 (intermediate) |
| Covariance inside a cluster | diagonal | correlated (factor model, strength 0.5, 3 factors) | diagonal |
| Standard deviation per variable | 1.0 | 1.0 (before correlation) | in [0.6, 1.4] per variable and cluster |
| Outliers | 0% | 0% | 2% (label $-1$) |
| Skewed (log-normal) variables | no | yes (7 of 20) | no |
| Clipping to physiological limits | no | yes | yes (clinical variables only) |
| What it tests | correctness, scaling reference | slow convergence, choice of $K$, diagonal model mismatch | numerical stability: rare group, outliers, high $D$ |

- `synth_overlap` has correlated variables, so the **diagonal model is wrong on purpose** for it, while the full model is not.
- In `synth_rare` the unequal cluster sizes do **not** unbalance the MPI ranks (every point costs the same): it tests numerical stability (empty or collapsing clusters, underflow, regularization), not load balancing.

### 3.4 Sizes and work per rank

**Weak scaling.** With $N_0 = 250\,000$ rows per process, the file for $p$ processes has $N = N_0 \cdot p$ rows and rank $r$ reads rows $[r N_0, (r+1) N_0)$: every rank always has $N_0$ rows. The files are nested: the file for $2p$ contains the one for $p$ plus $N_0$ new rows, so only the amount of data changes, not the sample.

**Strong scaling.** The largest file (`_p16`, $N = 4\,000\,000$) is run with $p \in \{1,2,4,8,16\}$; rank $r$ reads $N/p$ rows. No extra file is needed.

| $p$ | Rows | `synth_clean` | `synth_overlap` | `synth_rare` | Labels |
|---|---|---|---|---|---|
| 1 | 250 000 | 20 MB | 40 MB | 100 MB | 1 MB |
| 2 | 500 000 | 40 MB | 80 MB | 200 MB | 2 MB |
| 4 | 1 000 000 | 80 MB | 160 MB | 400 MB | 4 MB |
| 8 | 2 000 000 | 160 MB | 320 MB | 800 MB | 8 MB |
| 16 | 4 000 000 | 320 MB | 640 MB | 1 600 MB | 16 MB |
| **Total** | | **620 MB** | **1 240 MB** | **3 100 MB** | **31 MB** |

The table gives the size of the file for $p$ (weak scaling). Read in reverse it is also the data per rank in strong scaling: with the `_p16` file and $p$ processes, each rank holds as many rows as the file for $16/p$ processes (e.g. $p = 4$: 1 000 000 rows per rank, the row $p = 4$). Total on disk: about 5 GB. Sizes: $8 + 8ND$ bytes for the data, $4N$ for the labels (MB = $10^6$ bytes).

Work per rank, proportional to the cost of an iteration ($N \cdot K \cdot D / p$; operation counts, not measured times):

| | `synth_clean` | `synth_overlap` | `synth_rare` |
|---|---|---|---|
| Weak scaling, any $p$ ($N_0 K D$) | $1.0 \cdot 10^7$ | $2.5 \cdot 10^7$ | $7.5 \cdot 10^7$ |
| Strong scaling, $p = 1$ | $1.6 \cdot 10^8$ | $4.0 \cdot 10^8$ | $1.2 \cdot 10^9$ |
| Strong scaling, $p = 16$ | $1.0 \cdot 10^7$ | $2.5 \cdot 10^7$ | $7.5 \cdot 10^7$ |

Strong scaling halves the work per rank at every doubling of $p$; at $p = 16$ it meets the weak scaling. `synth_rare` costs about 7.5 times `synth_clean` per rank, which gives different regimes (memory-bound for small $D$, closer to compute-bound for large $D$).

Ideal behaviour: weak scaling, constant time ($E = T_1/T_p$); strong scaling, time halves when $p$ doubles ($S = T_1/T_p$, $E = S/p$).

### 3.5 How the data are generated

1. **True model.** Means and covariances of the $K$ clusters are drawn once with a fixed seed.
   - Means: each coordinate is Gaussian with standard deviation $\delta / \sqrt{2D}$, so the distance between two means is about $\delta$ whatever $D$ is.
   - Correlated covariance (`synth_overlap`): factor model $C = I + 0.5 \cdot B B^T$, $B$ of size $D \times 3$, normalized to a correlation matrix; one per cluster. Few factors give the low-rank structure typical of clinical variables (age, weight, metabolic state).
2. **Rows.** For each row the subgroup is drawn with the weights, then the point from that Gaussian.
3. **Outliers** (`synth_rare`): 2% of the points are replaced by Gaussian noise with standard deviation 4.0 and labelled $-1$.
4. **Clinical units.** Skewed variables become log-normal (`mean · exp((std/mean) · z)`), the others `mean + std · z`; with clipping on, values are limited to the physiological interval.
5. **Standardization.** z-score per column, with mean and standard deviation estimated on a pilot sample of 200 000 rows, the same for all the files of a profile (saved in the `.json`).

Every block of rows has its own random generator derived from (seed, profile, block), so the same seed always gives identical files.

### 3.6 Limitations

- Generic values chosen by us: the datasets reproduce the **structure** of clinical data (subgroups, correlations, skewness, outliers), not real patients. No privacy issues.
- `synth_overlap` is correlated while the diagonal model is not: the mismatch is intentional.
- Nested files: the weak scaling files share their first rows. The comparison is cleaner, but the measurements for different $p$ are not independent samples.

### 3.7 K and D sweeps

**Purpose.** Section 3.1 says that an iteration costs about $N \cdot K \cdot D$ (diagonal model) and $N \cdot K \cdot D^2$ (full model). The scaling datasets cannot check this, because between `synth_clean`, `synth_overlap` and `synth_rare` $K$, $D$ and the structure of the data all change at once. The sweeps change **one parameter at a time**, with $N$, the layout and everything else fixed, and measure the time per iteration. On a log-log plot the expected slopes are:

| | vs $K$ | vs $D$ |
|---|---|---|
| Diagonal, $O(NKD)$ | 1 | 1 |
| Full, $O(NKD^2)$ | 1 | 2 |

A different slope is a result to discuss: for example, the caches for large $D$, or the $O(KD^3)$ factorizations of the full model, which do not depend on $N$.

**K sweep.** Dataset `synth_clean_p01` ($N = 250\,000$, $D = 10$, 4 true clusters), run with $K \in \{2, 4, 8, 16, 32, 64\}$ (only the `-k` option changes). No new file is needed. The data have 4 true clusters for every $K$, so the number of iterations to converge changes with $K$. The time **per iteration** does not depend on it.

**D sweep.** Five files `synth_sweep_dDDD`, $D \in \{5, 10, 20, 35, 50\}$, run with $K = 4$. They use the same parameters as `synth_clean`: 4 clusters of 25%, $\delta = 6.0$, diagonal covariance, standard deviation 1.0, no outliers, no skewness, no clipping. Only $D$ changes. Beyond 20 variables the columns are the generic biomarkers of 3.3. One file per profile ($p = 1$, $N_0 = 250\,000$ rows):

| File | $D$ | Data | Labels | Work $NKD$ (diagonal) | Work $NKD^2$ (full) |
|---|---|---|---|---|---|
| `synth_sweep_d005_p01.bin` | 5 | 10 MB | 1 MB | $5.0 \cdot 10^6$ | $2.5 \cdot 10^7$ |
| `synth_sweep_d010_p01.bin` | 10 | 20 MB | 1 MB | $1.0 \cdot 10^7$ | $1.0 \cdot 10^8$ |
| `synth_sweep_d020_p01.bin` | 20 | 40 MB | 1 MB | $2.0 \cdot 10^7$ | $4.0 \cdot 10^8$ |
| `synth_sweep_d035_p01.bin` | 35 | 70 MB | 1 MB | $3.5 \cdot 10^7$ | $1.2 \cdot 10^9$ |
| `synth_sweep_d050_p01.bin` | 50 | 100 MB | 1 MB | $5.0 \cdot 10^7$ | $2.5 \cdot 10^9$ |
| **Total** | | **240 MB** | **5 MB** | | |

`synth_sweep_d010` has the same parameters as `synth_clean`, but it is a separate profile with its own seed, so its rows are not the rows of `synth_clean_p01`.

**Generation.** The files go to `data/synthetic/synth_sweep_dDDD/` and are deterministic. The random seed of a profile depends on its position in the full list of profiles, so generating only these 5 files gives the same bytes as generating everything:

```bash
python3 src/dataset-managed/generate-synthetic-dataset.py --profiles \
    synth_sweep_d005 synth_sweep_d010 synth_sweep_d020 synth_sweep_d035 synth_sweep_d050
# or: --sweep  (regenerates the base profiles too, about 5 GB)
```

**Runs.** `src/script/pemc-submit.sh sweep` submits 16 jobs: (K sweep, D sweep) × the 8 versions (sequential, baseline, opt1 and opt2, diagonal and full; `SWEEP_VERSIONS` selects a subset). The MPI+OpenMP versions use one fixed layout, 1 node × 1 rank × 8 threads, `pack:excl`. The sequential versions use 1 core on an exclusive node. Every point is repeated 3 times. The logs go to `results/logs/sweep/`, apart from the scaling logs, because the same dataset appears there with several $K$. The plot is `python3 src/plots-generate/plots-performance.py --plots P1`.

**Limit.** The sweeps measure **time** only. The memory of a run is not logged: the `bytes` key of the log is the analytic memory traffic of `include/perfmodel.h`, not the memory used.

### 4.2 Preprocessing

- The raw files are kept as served by the source; the conversion keeps only the numeric columns (identifiers removed), drops constant columns and standardizes every column (z-score).
- A dataset with empty cells in the numeric columns is **discarded, not imputed** (EM needs a complete matrix; imputing would invent data). None of the datasets above has any (section 5).
- The labels are written to `<name>_labels.bin` only when categorical, and are used only to measure ARI, purity and Dice, never by EM.

### 4.3 BrainWeb

- Only the T1 image is used (181 x 256 x 256, 1 mm): $N$ = 11 862 016 voxels with $D = 1$. T2 and T2* were dropped (the server download did not complete).
- The ground truth is the `crisp` volume (labels 0–11, 362 x 434 x 362, 0.5 mm): it is subsampled by 2 and placed on the T1 grid at the offset (0, 19, 38), found by FFT cross-correlation of the brain masks ($\eta^2 = 0.951$).
- The NIfTI affines of these files are inconsistent and must not be used.
